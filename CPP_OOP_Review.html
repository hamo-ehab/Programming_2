C++ OOP Final Review

المراجعة الذهبية الشاملة لكامل منهج البرمجة كائنية التوجه (C++ OOP) لتضمن الدرجة النهائية في الامتحانات بأبسط وأقوى أسلوب.

1. الكلاسات والكائنات ودورة الحياة (Classes, Objects & Lifecycle)

**الكلاس (Class)** هو المخطط الهندسي أو الكتالوج (Blueprint) الذي يصف حالة وسلوك الكائن، بينما **الكائن (Object)** هو التطبيق الفعلي أو الكيان الملموس (Instance) الذي يتم بناؤه في الذاكرة بناءً على هذا المخطط.

البرمجة الإجرائية (Procedural)

  • تعتمد على التفكير التنازلي (Top-Down).
  • البيانات معزولة تماماً عن الدوال التي تعالجها.
  • التركيز الكامل على "الخطوات والتعليمات المتتالية".

البرمجة كائنية التوجه (OOP)

  • تعتمد على التفكير التصاعدي (Bottom-Up).
  • تجميع البيانات والدوال معاً داخل وحدة واحدة (Object).
  • حماية البيانات والتواصل المباشر والآمن بين الكائنات.

محددات الوصول وحماية البيانات (Access Modifiers & Data Hiding):

نستخدم **الكبسلة (Encapsulation)** لحماية خصائص الكلاس وجعلها مخفية عن العالم الخارجي، ونوفر دوال وصول عامة (Getters / Setters) للتحكم في البيانات بأمان.

  • private: الأعضاء لا يمكن لأحد رؤيتها أو تعديلها إلا دوال الكلاس نفسه (الديفولت في الكلاس).
  • protected: الأعضاء مرئية فقط للكلاس نفسه ولجميع الكلاسات التي ترث منه (الأبناء والأحفاد).
  • public: الأعضاء متاحة ومكشوفة للجميع داخل وخارج الكلاس وفي الـ main.

المشيدات والمهدمات (Constructors & Destructors):

  • المشيد (Constructor): دالة استثنائية تُستدعى تلقائياً فور ولادة الكائن في الذاكرة. لها نفس اسم الكلاس وليس لها نوع إرجاع (حتى void).
  • مشيد النسخ التلقائي (Default Copy Constructor): يقوم بنسخ كائن إلى كائن آخر من نفس النوع (Member-wise Copy). ولكن إذا كان الكلاس يحتوي على مؤشرات وحجز ذاكرة ديناميكية، يجب كتابة مشيد نسخ مخصص لتجنب مشاكل الذاكرة (Deep Copy).
  • المهدم (Destructor): دالة استثنائية تبدأ بـ ~ وتُستدعى تلقائياً فور انتهاء دورة حياة الكائن لتنظيف وتفريغ الذاكرة المحجوزة ديناميكياً.
class_lifecycle.cpp
#include <iostream>
#include <string>
using namespace std;

class Student {
private:
    string name;
    double* gpa; // ذاكرة ديناميكية تحتاج لتنظيف عميق

public:
    // مشيد بارامتري مع قائمة التهيئة
    Student(string n, double g) : name(n) {
        gpa = new double(g);
        cout << "[Constructor] Created student: " << name << " with GPA: " << *gpa << endl;
    }

    // مشيد نسخ مخصص لحل مشكلة الذاكرة (Deep Copy Constructor)
    Student(const Student& other) {
        name = other.name;
        gpa = new double(*other.gpa); // حجز مكان جديد في الذاكرة ونسخ القيمة
        cout << "[Copy Constructor] Deep copied student: " << name << endl;
    }

    // مهدم الكلاس لتنظيف الرام ومنع تسريب الذاكرة
    ~Student() {
        delete gpa; // تفريغ الذاكرة
        cout << "[Destructor] Deallocated GPA memory for: " << name << endl;
    }
};

int main() {
    Student s1("Zain", 3.95);
    Student s2 = s1; // استدعاء مشيد النسخ
    return 0;
}

2. التحميل الزائد والأعضاء الساكنة (Overloading & Static Members)

تحميل الدوال والمشيدات (Method & Constructor Overloading):

تتيح لك لغة C++ إعلان أكثر من دالة أو مشيد بنفس الاسم تماماً، بشرط أن يختلف **التوقيع (Signature)**. والتوقيع يختلف باختلاف: **عدد البارامترات، أو نوعها، أو ترتيبها**.

تحميل العمليات الزائد (Operator Overloading):

تسمح لنا بإعطاء الرموز الرياضية والمنطقية الأساسية (مثل +, -, ==, ++) سلوكاً جديداً عندما تُستخدم مع الكائنات التي نصنعها، لتسهيل قراءة الكود وجعله طبيعياً.

المهندس الكبير بيقولك بالبلدي:

بص يا هندسة، الأعضاء الساكنة (Static Members) دي بتعامل كأنها "أصول مشتركة" في الشركة! المتغير الـ Static مبيتحجزش منه نسخة لكل كائن، هي نسخة واحدة يتيمة في الذاكرة بيشاركوها كل الكائنات مع بعض. والدالة الـ Static متقدرش تقرأ أي متغير عادي في الكلاس إلا لو كان Static هو كمان، لأنها بتشتغل باسم الكلاس مباشرة بدون ما تعمل كائن!

مثال شامل لتحميل العمليات والأعضاء الساكنة:

static_and_operators.cpp
#include <iostream>
using namespace std;

class Counter {
private:
    int value;

public:
    // متغير ساكن مشترك بين كل الكائنات لحساب العدد الكلي
    static int totalCounters; 

    Counter(int val = 0) : value(val) {
        totalCounters++; // زيادة العدد الكلي فور بناء كائن جديد
    }

    // دالة ساكنة تعمل باسم الكلاس مباشرة
    static int getTotalCounters() {
        return totalCounters; 
    }

    // تحميل المعامل الثنائي + لجمع قيم كاونترين معاً
    Counter operator+(const Counter& other) {
        return Counter(this->value + other.value);
    }

    void display() const {
        cout << "Counter Value: " << value << endl;
    }
};

// تهيئة المتغير الساكن خارج الكلاس (إلزامي في C++)
int Counter::totalCounters = 0;

int main() {
    Counter c1(10);
    Counter c2(20);
    
    Counter c3 = c1 + c2; // جمع الكائنات بشكل طبيعي جداً!
    c3.display();         // هيطبع: 30

    // استدعاء الدالة الساكنة باسم الكلاس
    cout << "Total Counters Created: " << Counter::getTotalCounters() << endl; // هيطبع: 3
    return 0;
}

3. الوراثة وتعدد الأشكال والصداقة (Inheritance & Polymorphism & Friend)

الوراثة وأوضاعها (Inheritance & Access Modes):

الوراثة تمكننا من إنشاء كلاس جديد بناء على كلاس موجود لتوفير الكود وتسهيل التعديل. الوراثة تمثل علاقة **"Is-A"**.

  • الوراثة العامة (Public): تظل خصائص الأب العامة عامة في الابن، والخصائص المحمية تظل محمية.
  • الوراثة المحمية (Protected): تتحول خصائص الأب العامة والمحمية إلى محمية داخل الابن.
  • الوراثة الخاصة (Private): تتحول جميع خصائص الأب العامة والمحمية إلى خاصة ومخفية تماماً داخل الابن.
  • ملاحظة هامة: الخصائص الخاصة (Private) الخاصة بالأب لا يمكن للابن الوصول إليها مباشرة تحت أي نوع وراثة!

تعدد الأشكال والدوال الافتراضية (Polymorphism & Virtual Functions):

تعدد الأشكال الديناميكي (Run-time Polymorphism) يعتمد على استخدام **مؤشر الأب (Base Pointer)** للإشارة إلى كائن الابن، واستدعاء الدوال الافتراضية المعلنة بكلمة virtual ليوجه C++ الكود لتشغيل الدالة الصحيحة في الابن المناسب فوراً.

الكلاسات المجردة (Abstract Classes):

يصبح الكلاس مجرداً إذا كان يحتوي على دالة افتراضية نقية واحدة على الأقل (virtual int func() = 0;). هذا الكلاس يمنع C++ بناء أي كائنات منه مباشرة، ويستخدم فقط كواجهة وعقد إجباري للأبناء لتطبيق الدوال وتوحيد الهيكل.

دوال وفئات الصداقة (Friend Function & Class):

  • الدالة الصديقة (Friend Function): دالة خارجية ليست عضواً في الكلاس، ولكن يُعطى لها تصريح أمني بقراءة وتعديل متغيرات الكلاس الخاصة والمحمية مباشرة.
  • الكلاس الصديق (Friend Class): كلاس خارجي بالكامل يُسمح لجميع دواله بالوصول المباشر لسرية الكلاس المانح للصداقة.
  • قواعد الصداقة: الصداقة ليست متبادلة، وليست موروثة على الإطلاق.
poly_and_friend.cpp
#include <iostream>
using namespace std;

// كلاس مجرد (Abstract Class)
class Employee {
protected:
    string name;
public:
    Employee(string n) : name(n) {}
    
    // دالة افتراضية نقية
    virtual double getSalary() = 0; 
};

class Developer : public Employee {
private:
    double basePay;
public:
    Developer(string n, double pay) : Employee(n), basePay(pay) {}
    
    double getSalary() override {
        return basePay + 1500; // راتب المطور مع الحوافز
    }

    // إعلان دالة فاحصة خارجية كصديقة لقراءة الراتب الأساسي السري
    friend void printSecretSalary(Developer dev);
};

void printSecretSalary(Developer dev) {
    // الوصول للمتغير الخاص basePay مباشرة بدون Getters!
    cout << "[Audit System] Developer secret base salary: $" << dev.basePay << endl;
}

int main() {
    Employee* emp = new Developer("Zain", 8000);
    
    // استدعاء دالة الراتب الكلي ديناميكياً عن طريق مؤشر الأب
    cout << "Total Pay: $" << emp->getSalary() << endl; // هيطبع: 9500

    Developer devObj("Zain", 8000);
    printSecretSalary(devObj);

    delete emp;
    return 0;
}

Final Master Coding Challenge:

Ultimate C++ Exam Challenge: Academic Portal
Design a complete C++ OOP hierarchy where: 1. Abstract base class Member with protected name, parameterized constructor, and a pure virtual function showRole() = 0. 2. Derived class Professor that has a static count of total professors, overrides showRole(), and has a friend class PortalAuditor. 3. Friend class PortalAuditor that prints professor details including the secret academic research rank directly.

تحليل الحل البرمجي الشامل:

بص يا هندسة، ده حل نهائي ممتاز ومحكم بيطبق الـ Abstract Class والـ static members والـ Friend Class مع الـ runtime polymorphism في كود واحد متناسق:

academic_portal.cpp
#include <iostream>
#include <string>
using namespace std;

class Member {
protected:
    string name;

public:
    Member(string n) : name(n) {}
    virtual void showRole() = 0; // Pure Virtual Function
    virtual ~Member() {}
};

class Professor : public Member {
private:
    string researchRank;

public:
    static int profCount; // متغير ساكن

    Professor(string n, string rank) : Member(n), researchRank(rank) {
        profCount++;
    }

    void showRole() override {
        cout << "Professor: " << name << " | Department: Computer Science" << endl;
    }

    static int getProfCount() {
        return profCount;
    }

    friend class PortalAuditor; // الكلاس الصديق
};

int Professor::profCount = 0; // تهيئة المتغير الساكن

class PortalAuditor {
public:
    void auditProfessor(const Professor& prof) {
        // الوصول المباشر للمتغيرات الخاصة والمحمية
        cout << "[Portal Audit Logs] Checking Access Rights for " << prof.name << endl;
        cout << "Research Rank: " << prof.researchRank << " | Approved Status: Active." << endl;
    }
};

int main() {
    // 1. استخدام تعدد الأشكال
    Member* user = new Professor("Dr. Amr Megahed", "Senior Assistant Professor");
    user->showRole(); // استدعاء ديناميكي

    // 2. استخدام الكلاس الصديق
    Professor* profObj = static_cast(user);
    PortalAuditor auditor;
    auditor.auditProfessor(*profObj);

    // 3. استدعاء الميثود الساكنة
    cout << "Total Professors registered: " << Professor::getProfCount() << endl;

    delete user;
    return 0;
}
