1. مراجعة شاملة لأساسيات الـ C++

أ. الـ Inputs/Outputs والتعليقات (Comments)

في الـ C++ بنستخدم الـ std::cin عشان نستقبل الداتا من اليوزر، والـ std::cout عشان نطبع المخرجات على الشاشة. وطبعاً المكتبة المسؤولة عن دا هي الـ #include <iostream>.

cpp_basics.cpp
#include <iostream>
using namespace std;

int main() {
    // دا تعليق من سطر واحد (Single-line comment)
    /* 
       ودا تعليق من كذا سطر (Multi-line comment)
       بنستخدمه عشان نشرح الفكرة ورا الكود
    */
    int age;
    cout << "Enter your age: ";
    cin >> age;
    cout << "Your age is: " << age << endl;
    return 0;
}

الكومنتس دي بتعمل إيه؟

بص يا هندسة، الـ Comments دي الكومبيلر (Compiler) مش بيشوفها أصلاً، يعني بتكبر دماغها منها تماماً. دي معمولة عشانك أنت والـ Team اللي شغال معاك عشان تفهموا الكود دا كان بيعمل إيه لما ترجعوا له بعد شهور.

ب. تحويل الأنواع (Type Casting)

ساعات بنحتاج نغير نوع الداتا عشان نمنع حدوث أخطاء حسابية (Logical Bugs). أشهر مثال لدا هو قسمة الأرقام الصحيحة:

type_casting.cpp
// الكود دا فيه مشكلة منطقية:
int i = 5, j = 3;
float div = i / j; 
cout << div; // هيطبع 1 ! لأن قسمة integer على integer بتطلع integer وبتطير الكسر!

// الحل باستخدام الـ Type Casting:
float correctDiv = (float)i / j; 
cout << correctDiv; // هيطبع 1.66667 صح تماماً!

تحليل الكود سطر بسطر:

  • float div = i / j; هنا الكومبيلر بيقسم 5 على 3 كأعداد صحيحة أولاً والناتج بيكون 1، بعد كدا بيحطها في متغير float فيتحول لـ 1.0. ودي مشكلة شهيرة جداً!
  • (float)i هنا بنعمل **Casting** صريح، كأننا بنقول للكومبيلر: "اتعامل مع الـ i للحظة دي بس كأنها رقم عشري". فبالتالي القسمة هتتحول لقسمة عشرية وتطلع النتيجة بالكسر.

ج. الـ Increment/Decrement والتكرار (Loops)

لازم نفهم الفرق بين التزويد القبلي والتزويد البعدي في المعاملات:

  • ++x (Pre-increment): بيزود الأول في الميموري، وبعد كدا بيستخدم القيمة الجديدة في العملية الحسابية.
  • x++ (Post-increment): بيستخدم القيمة القديمة الأول في العملية الحسابية، وبعد كدا بيزود في الميموري.
loops_tricks.cpp
// خدعة شهيرة في الـ Loops:
int i;
for (i = 0; i++ < 10; ) {
    // Loop جسمه فاضي
}
cout << i; // هيطبع كام برة اللوب؟ هيطبع 11!

// مثال على الـ do-while اللي بيتنفذ مرة واحدة على الأقل غصب عن الشرط:
int k = 11;
do {
    cout << k << " ";
    k += 5;
} while (k <= 10); // هيطبع 11 وبعدين يخرج برة اللوب!

د. تمرير المعاملات (Value vs Reference Parameters)

لما بنبعت متغير للفانكشن، عندنا طريقتين:

  1. Pass by Value: بنبعت نسخة من المتغير. لو غيرنا قيمته جوة الفانكشن، المتغير الأصلي برة مش هيتأثر.
  2. Pass by Reference: بنبعت عنوان المتغير الأصلي باستخدام الـ &. أي تغيير جوة الفانكشن هيغير المتغير الأصلي برة فوراً!
references.cpp
#include <iostream>
using namespace std;

// دالة التبديل الشهيرة باستخدام الـ Reference
void swap(int &x, int &y) {
    int temp = x;
    x = y;
    y = temp;
}

int main() {
    int a = 10, b = 20;
    swap(a, b);
    cout << "a: " << a << " | b: " << b; // هيطبع a: 20 | b: 10
    return 0;
}

ليه الـ Swap دي نجحت؟

  • void swap(int &x, int &y) علامة الـ **`&`** دي معناها إننا استقبلنا الـ **Memory Address** بتاع المتغيرات الحقيقية. يعني الفانكشن بتعدل مباشرة على مكان a و b في الرامات!

2. الانتقال إلى البرمجة كائنية التوجه (OOP)

في البرمجة الهيكلية (Structured Programming) اللي درسناها قبل كدا، كنا بنفصل البيانات (Variables) عن الدوال (Functions) اللي بتشتغل عليها. المشكلة دي كانت بتعمل لخبطة لما المشروع يكبر!

الـ OOP حلت المشكلة دي تماماً بإنها جمعت البيانات والدوال اللي بتخدمها جوة علبة واحدة سميناها Class، ومنه بنقدر ناخد نسخ حقيقية اسمها Objects.

مثال عملي: نظام أمان المنزل الذكي (Smart Home Security)

تخيل إننا شغالين في شركة بتعمل أنظمة أمان ذكية، وعايزين نعمل برنامج للتحكم في قفل الباب (Door Lock) وتسجيل عمليات الفتح والقفل (Access Logs). لو عملناها بالبرمجة العادية، المتغيرات هتكون سايحة في الكود. لكن مع الـ OOP، هنعمل كلاس اسمه DoorLock وكلاس تاني اسمه AccessLog يمثلوا الكيان دا بالكامل!

بناء الكلاسات وتطبيق مبدأ الـ Encapsulation

الكود اللي جاي بيوضح إزاي نبني كلاس متكامل بيحتوي على Constructor و Destructor ودوال داخلية، وبيخزن التواريخ والأوقات تلقائياً باستخدام الـ std::vector:

smart_security.cpp
#include <iostream>
#include <string>
#include <vector>
#include <ctime>

using namespace std;

// كلاس لتخزين أوقات فتح الباب
class AccessLog {
private:
    vector<string> timestamps; // مخفي ومحمي جوة الكلاس (Encapsulation)

public:
    void addLog(const string& timestamp) {
        timestamps.push_back(timestamp);
    }

    void showLogs() const {
        cout << "--- Access Log History ---" << endl;
        for (const auto& log : timestamps) {
            cout << "[LOG] Door opened at: " << log << endl;
        }
    }
};

// الكلاس الأساسي للتحكم بالقفل الذكي
class DoorLock {
private:
    string lockID;
    bool isLocked;
    AccessLog log; // تركيب كلاس جوة كلاس (Composition)

public:
    // 1. الباني (Constructor): بيشتغل تلقائياً عند إنشاء الكائن
    DoorLock(string id) {
        lockID = id;
        isLocked = true; // الباب بيتقفل أول ما يتثبت السيستم
        cout << "[System] DoorLock " << lockID << " has been Initialized." << endl;
    }

    // 2. الهادم (Destructor): بيشتغل تلقائياً عند تدمير الكائن
    ~DoorLock() {
        cout << "[System] DoorLock " << lockID << " shutting down safely." << endl;
    }

    // دالة لفتح الباب وتسجيل الوقت
    void unlock() {
        if (isLocked) {
            isLocked = false;
            cout << "[Action] Door " << lockID << " is now UNLOCKED." << endl;
            
            // جلب الوقت الحالي لتسجيله
            time_t now = time(0);
            char* dt = ctime(&now);
            string ts(dt);
            ts.pop_back(); // حذف العلامة السطرية الجديدة
            log.addLog(ts);
        } else {
            cout << "[Warning] Door is already unlocked." << endl;
        }
    }

    void lock() {
        isLocked = true;
        cout << "[Action] Door " << lockID << " is now LOCKED." << endl;
    }

    void displayStatus() const {
        cout << "=== Device Info ===" << endl;
        cout << "Device ID: " << lockID << endl;
        cout << "Status: " << (isLocked ? "LOCKED" : "UNLOCKED") << endl;
        log.showLogs();
    }
};

int main() {
    // إنشاء كائن (Object) من الكلاس DoorLock
    DoorLock frontDoor("FRONT_GATE_01");
    
    // محاكاة فتح وقفل الباب
    frontDoor.unlock();
    frontDoor.lock();
    frontDoor.unlock();
    
    // عرض الحالة والسجلات
    frontDoor.displayStatus();
    
    return 0; // هنا الـ Object هيموت والـ Destructor هيشتغل تلقائياً!
}

شرح تفصيلي للأسطر المعقدة:

  • class AccessLog { private: vector<string> timestamps; ... } هنا طبقنا الـ **Encapsulation**. المتغير timestamps محمي بـ private، مفيش أي كود من برة يقدر يمسحه أو يعدل عليه مباشرة، التعديل بيتم بس من خلال الدالة العامة addLog().
  • DoorLock(string id) دا الـ **Constructor** (الباني). دالة خاصة جداً، اسمها بيبقى نفس اسم الكلاس ومفيش ليها return type. بتشتغل تلقائياً أول ما نكتب DoorLock frontDoor("...") عشان تأهل الرامات وتثبت القيم الافتراضية.
  • ~DoorLock() دا الـ **Destructor** (الهادم). بيبدأ بعلامة الـ (Tilde) `~`. بيشتغل تلقائياً في نهاية البرنامج أو لما الكائن يخرج برة الـ Scope بتاعه عشان يفضي أي رامات محجوزة وينظف وراه السيستم.
  • AccessLog log; // inside DoorLock دا مبدأ الـ **Composition** (التركيب). الباب الذكي بيحتوي على سجل الوصول كعضو داخلي جواه، كأن الكلاس التاني بقى جزء لا يتجزأ من الكلاس الأول.

3. قاموس مصطلحات الـ OOP والمفاهيم البرمجية

بص يا هندسة، عشان ندخل على البرمجة بقلب جامد، لازم تكون عارف المصطلحات البرمجية بالإنجليزي وبالعربي اللي بنسمعه في الشركات. تقدر تستخدم مربع البحث دا عشان تدور على أي مصطلح فوراً:

المصطلح بالإنجليزي (English) المسمى بالعربي (Arabic) الشرح بالبلدي الهندسي (Egyptian Explanation)
Class الفئة / الكلاس عامل زي الكتالوج أو الرسم الهندسي (Blueprint). مش بيحجز مكان في الميموري، هو بس بيوصف شكل المتغيرات والدوال اللي هتبقى جوة الكائنات لما تتخلق.
Object الكائن / الأوبجكت النسخة الفعلية اللي بنيناها بناءً على الكتالوج (الكلاس). الأوبجكت دا بيتحجز له مكان حقيقي في الرامات وبيبقى ليه قيمة وحالة خاصة بيه.
Encapsulation تغليف وإخفاء البيانات إنك تجمع الداتا والدوال في كبسولة واحدة، وتخفي البيانات الحساسة خلف جدار الـ private عشان تحميها من اللعب الخارجي، وتوفر دوال تحكم عامة public.
Inheritance الوراثة توفير للوقت والمجهود! كلاس جديد (Derived) بياخد كل الخصائص والدوال من كلاس قديم (Base)، ويقدر يضيف خصائص جديدة من غير ما نعيد كتابة الكود من الصفر.
Polymorphism تعدد الأشكال إن نفس الدالة يكون ليها كذا شكل وكذا تطبيق حسب الكلاس اللي بيناديها، ودا بنعمله عن طريق الـ virtual functions.
Abstraction التجريد إنك تخفي التفاصيل المعقدة للسيستم وتظهر للمستخدم بس الزراير أو الدوال اللي محتاجها عشان يشتغل. زي كابينة العربية: أنت ليك الدريكسيون والفرامل، ومش لازم تعرف الموتور شغال إزاي من جوة.
Constructor الدالة البانية أول فانكشن بتشتغل تلقائياً أول ما الأوبجكت يتخلق. بنستخدمها عشان ندي قيم افتراضية للمتغيرات ونحجز رامات لو محتاجين.
Destructor الدالة الهادمة الفانكشن اللي بتشتغل لوحدها لما الأوبجكت يقرر يموت ويخرج برة الميموري. مهمتها تنضف ورانا وتفضي أي ذاكرة ديناميكية محجوزة.
Composition التركيب علاقة بين الكلاسات بنسميها (Has-A). يعني كلاس جواه كائن من كلاس تاني، زي الباب الذكي اللي جواه سجل الأحداث بتاعه.

Practical Challenges:

Challenge 1: Find the error and fix it!
The following code contains a compilation error due to OOP principles. Find the error and propose a way to solve it while preserving the principle of Encapsulation. 
#include <iostream>
using namespace std;

class SmartLight {
    bool isOn; // state of smart light
public:
    SmartLight() { isOn = false; }
};

int main() {
    SmartLight light;
    light.isOn = true; // attempt to access private member directly
    return 0;
}

الحل البرمجي الصحيح:

بص يا هندسة، الغلطة هنا هي إن المتغير isOn معرّف كـ private افتراضياً (لأن في لغة الـ C++ أي حاجة جوة الكلاس مش مكتوب قبليها كلمة public أو private بتعتبر private تلقائياً). وعشان كدا الـ main مش قادرة تشوفه.

عشان نصلح الكود مع الحفاظ على الـ **Encapsulation**، لازم نخلي الداتا مخفية ونعمل دالة عامة (Setter) تغير القيمة دي بطريقة آمنة:

smart_light_fixed.cpp
#include <iostream>
using namespace std;

class SmartLight {
private:
    bool isOn; // محمي ومخفي

public:
    SmartLight() { isOn = false; }

    // دالة عامة لتغيير الحالة (Setter/Interface)
    void turnOn() {
        isOn = true;
        cout << "Light is now turned ON." << endl;
    }

    void turnOff() {
        isOn = false;
        cout << "Light is now turned OFF." << endl;
    }
};

int main() {
    SmartLight light;
    light.turnOn(); // تمام جداً وبطريقة آمنة 100%!
    return 0;
}
Challenge 2: Writing a Derived Class (Inheritance)
Write a new class named SirenDoorLock that inherits from the base class DoorLock built in part 3. It should add a private boolean property for the Siren, and provide functions triggerSiren() to start the siren and stopSiren() to stop it.

الحل البرمجي للوراثة (Inheritance Code):

بص يا هندسة، عشان نورث من الكلاس DoorLock، بنستخدم علامة النقطتين فوق بعض والكلمة المفتاحية public. ولازم نبعت الـ parameter للـ Constructor بتاع الأب من خلال الـ **Initialization List** زي ما هو موضح تحت:

inheritance_solution.cpp
#include <iostream>
#include <string>
// هنفترض إن الكلاس DoorLock مبني فوق بالفعل

class SirenDoorLock : public DoorLock {
private:
    bool sirenActive; // خاصية السارينة المضافة للكلاس الابن بس

public:
    // الباني هنا بيمرر الـ ID للكونستركتور بتاع الأب (DoorLock)
    SirenDoorLock(std::string id) : DoorLock(id), sirenActive(false) {
        std::cout << "[Siren System] Anti-theft alarm system loaded." << std::endl;
    }

    void triggerSiren() {
        sirenActive = true;
        std::cout << "[WARNING!!!] ALARM TRIGGERED! INTRUSION DETECTED ON DEVICE!" << std::endl;
    }

    void stopSiren() {
        sirenActive = false;
        std::cout << "[Siren System] Alarm secured and turned off." << std::endl;
    }
};
