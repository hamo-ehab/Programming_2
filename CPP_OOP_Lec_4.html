المنشئات والمهدمات وتغليف الكائنات

الكبسلة (Encapsulation)، بناء الكائنات تلقائياً بالمنشئات (Constructors)، قوائم التهيئة (Initialization Lists)، وتفكيك الميموري بالمهدمات (Destructors)

تغليف الكائنات (Encapsulation)

بص يا هندسة، الـ **Encapsulation** (الكبسلة) هي أول عمود من أعمدة الـ OOP الأربعة. الفكرة بكل بساطة إنك بتعمل كبسولة برمجية تجمع جواها البيانات (Variables) والدوال اللي بتتحكم فيها (Methods) وتمنع أي وصول عشوائي خارجي ليها.

الخاصيتين الذهبيتين للتغليف (Two Properties of Encapsulation):

  1. حماية البيانات (Data Protection): حماية حالة الكائن (Internal State) عن طريق جعل المتغيرات بالكامل private، والتعديل عليها يكون حصراً عبر دوال التحكم الـ public.
  2. إخفاء التفاصيل (Information Hiding): إخفاء تفاصيل الهيكلة الداخلية عن المبرمجين التانيين؛ بنوفرلهم واجهة تحكم بسيطة جاهزة (Public Interface) يقدروا يستدعوها بدون ما يعرفوا إحنا حسبناها إزاي جوة الكلاس!

شرط الكبسلة الهام في السلايدات!

عشان نطلق علمياً لفظ **Encapsulation** على دالة جوة الكلاس، **لازم ولابد** تكون الدالة دي بتستعمل متغيرات الكلاس الأعضاء (Member Variables) للتحكم فيها. لو الدالة مش بتستعمل المتغيرات دي، فده مش كبسلة!

جدول مصطلحات الكبسلة والمنشئات (Glossary):

المصطلح العلمي (English) المعنى البرمجي (Arabic) الشرح المبسط بالبلدي
Encapsulation الكبسلة / التغليف تجميع الداتا والدوال في كبسولة حماية واحدة.
Constructor دالة البناء / المنشئ فانكشن خاصة بتشتغل لوحدها بمجرد ما الكائن يتولد عشان تديله قيمه البدئية.
Destructor دالة الهدم / المهدم فانكشن بتنظف الرامات وتدمر الكائن لما ينتهي دوره في السيستم.
Initialization List قائمة التهيئة طريقة سريعة وحديثة في الـ C++ لتهيئة المتغيرات قبل تشغيل جسم المنشئ.
Constructor Overloading زيادة تحميل المنشئ عمل كذا منشئ للكلاس ببارامترات مختلفة عشان نولد كائن بأكتر من طريقة.

دوال البناء (Constructors & Overloading)

بص يا هندسة، لو عملنا كائن من كلاس المستطيل في الرام ونسينا نديله طول وعرض بدئي، البرنامج هيكون جواه قيم عشوائية (Garbage Values) تسبب كوارث في الحسابات! عشان كدة الـ C++ وفرت لنا فانكشن خارقة بتشتغل تلقائياً أول ما نعمل الكائن، وهي الـ **Constructor**.

شروط وقواعد المنشئ (Constructor Rules):

  • نفس اسم الكلاس تماماً: لازم يتكتب بنفس الحروف وكابتل أو سمول زي الكلاس.
  • لا يمتلك نوع إرجاع (No Return Type): مفيش قبله ولا int ولا void ولا أي حاجة خالص!
  • تلقائي الاستدعاء: بينادي نفسه فور حجز الكائن في الميموري.
  • يمكن تحميله بأكثر من شكل (Overloading): يعني نعمل كذا منشئ بشرط اختلاف الـ **Signature** (عدد البارامترات، أنواعها، أو ترتيبها).

قائمة التهيئة المتطورة (Initialization Lists in C++):

الـ C++ بتوفر طريقة فائقة السرعة لتهيئة البيانات قبل الدخول لجسم المنشئ كالتالي:

// الطريقة التقليدية (Assignment inside body)
Rectangle() {
    length = 0;
    width = 0;
}

// الطريقة الاحترافية السريعة (C++ Initialization List)
Rectangle() : length(0), width(0) {
    // جسم المنشئ فاضي أو فيه أكواد تانية
}

الـ Default Constructor بالبلدي

لو إنت مكتبتش أي منشئ في الكلاس بتاعك، المترجم (Compiler) هيتبرع من عنده ويكتب منشئ افتراضي خفي فاضي **Default Constructor**.
**ملحوظة ذهبية:** لو إنت كتبت أي منشئ خاص بيك (حتى لو بياخد بارامترات)، الـ Compiler هيسحب تبرعه فوراً ويحذف المنشئ الافتراضي، ولو جيت تعمل كائن بدون بارامترات هيطلعلك خطأ، إلا لو كتبت بإيدك **No-Arg Constructor**!

دوال الهدم (Destructors) ومنشئ النسخ

زي ما بنهتم ببناء الكائنات وتهيئتها في الذاكرة، لازم نهتم بتنظيف الميموري لما الكائن ينتهي عمره عشان نمنع تسريب الميموري (**Memory Leak**). الفانكشن اللي بتعمل كدة اسمها الـ **Destructor**.

شروط دالة الهدم (Destructor Rules):

  • تبدأ بعلامة التيلدا (~): بنحط العلامة دي قبل اسم الكلاس مباشرة للتفريق بينها وبين المنشئ.
  • لا تأخذ بارامترات نهائياً: مفيش أقواس ببارامترات ليها، وبالتالي **لا يمكن عمل Overloading لها**؛ هو مهدم واحد لكل كلاس!
  • تلقائية الاستدعاء: بتنطلق فوراً لما الكائن يخرج برة الـ Scope بتاعه (زي قفلة قوس الـ main أو انتهاء الفانكشن).

منشئ النسخ الافتراضي (Default Copy Constructor):

بص يا هندسة، الـ C++ بتديك ميزة مجانية! لو إنت عندك كائن جاهز متخزن فيه بيانات وعايز تعمل كائن تاني نسخة طبق الأصل منه، المترجم بيوفر **Copy Constructor** افتراضي بينسخ كل العناصر مباشرة:

Rectangle rect1(10, 5); // كائن أصلي
Rectangle rect2 = rect1; // عمل كائن جديد ونسخ قيم rect1 فيه تلقائياً بالـ Copy Constructor!

التطبيق العملي: كلاس السيارة المتكامل (Car Class)

دلوقتي يا هندسة، هنبني كلاس **`Car`** متكامل بيوضح مفهوم الكبسلة الكاملة، مع تحميل كذا منشئ (Constructor Overloading) باستعمال قوائم التهيئة (Initialization Lists)، وتتبع لحظة تدمير الكائن بالـ Destructor!

car_simulation.cpp
#include <iostream>
#include <string>
using namespace std;

class Car {
private:
    string maker;      // الشركة المصنعة
    int yearModel;     // سنة الصنع

public:
    // 1. منشئ بدون بارامترات (No-Arg Constructor) باستخدام قائمة التهيئة
    Car() : maker("Unknown"), yearModel(2026) {
        cout << "[Constructor] Created car with default specs." << endl;
    }

    // 2. منشئ مخصص ببارامترات (Overloaded Constructor)
    Car(string make, int year) : maker(make), yearModel(year) {
        cout << "[Constructor] Created " << maker << " Model " << yearModel << "." << endl;
    }

    // دوال التعديل (Setters) مع التحقق من صحة الموديل
    void setMaker(string make) {
        maker = make;
    }

    void setYearModel(int year) {
        if (year >= 1886) { // أول سنة تم اختراع السيارة فيها
            yearModel = year;
        } else {
            cout << "Warning: Invalid year! Setting model to 2026." << endl;
            yearModel = 2026;
        }
    }

    // دوال القراءة (Getters)
    string getMaker() {
        return maker;
    }

    int getYearModel() {
        return yearModel;
    }

    // 3. المهدم (Destructor) لتتبع خروج الكائنات من الرامات
    ~Car() {
        cout << "[Destructor] Destroying " << maker << " Model " << yearModel << " and freeing memory!" << endl;
    }
};

int main() {
    cout << "--- Starting Program ---" << endl;

    {
        // كتلة ميموري مؤقتة لتوضيح دور الـ Destructor
        cout << "\nCreating Car 1 inside inner block:" << endl;
        Car car1("Tesla", 2024);
        cout << "Car 1 specs: " << car1.getMaker() << " (" << car1.getYearModel() << ")" << endl;
        cout << "Exiting inner block now..." << endl;
    } // هنا ينتهي عمر car1 وتستدعى دالة الهدم تلقائياً!

    cout << "\nCreating Car 2 in main scope:" << endl;
    Car car2; // تستدعي المنشئ الافتراضي بدون بارامترات
    car2.setMaker("Toyota");
    car2.setYearModel(2025);

    cout << "\nCreating Car 3 via Copy Constructor:" << endl;
    Car car3 = car2; // نسخ car2 بالكامل في car3
    cout << "Car 3 copy specs: " << car3.getMaker() << " (" << car3.getYearModel() << ")" << endl;

    cout << "\nEnd of main function..." << endl;
    return 0;
}

تتبع حركة الذاكرة والرامات:

  • Car(string make, int year) : maker(make), yearModel(year) دي قائمة تهيئة (Initialization List). الـ compiler بيحط القيم دي في الميموري للسيارة مباشرة وهي بتتخلق، أسرع بكتير من إسنادها جوة الأقواس.
  • Exiting inner block now... ثم ظهور [Destructor] Tesla بمجرد ما القوس المقفول للـ Block ينتهي، الـ C++ بتنادي المهدم فوراً لأن الكائن خرج برة نطاق الاستخدام لتوفير الرام!
  • Car car3 = car2; استعملنا **Copy Constructor** لتوليد نسخة جديدة مطابقة للقيم السابقة لـ Toyota بدون تكرار الكود.

Challenge 1: BankAccount Class
Build a class named BankAccount containing account number and balance as private variables. Design a custom constructor that initializes values using an initialization list. Design a deposit function and a withdraw function, ensuring that withdrawals exceeding the current balance are rejected.

تحليل الحل البرمجي:

بص يا هندسة، هنا بنحمي رصيد الحساب البنكي من العمليات الخاطئة (زي سحب مبلغ أكبر من الرصيد أو إيداع رقم سالب) باستعمال شروط أمان منطقية صارمة:

bank_account.cpp
#include <iostream>
#include <string>
using namespace std;

class BankAccount {
private:
    string accountNumber;
    double balance;

public:
    // منشئ مخصص بقائمة تهيئة (Initialization List)
    BankAccount(string accNum, double initialBal) : accountNumber(accNum), balance(initialBal) {
        if (balance < 0) {
            balance = 0;
        }
    }

    // دالة الإيداع مع حماية من القيم السالبة
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            cout << "Deposited: $" << amount << " | New Balance: $" << balance << endl;
        } else {
            cout << "Warning: Deposit amount must be positive!" << endl;
        }
    }

    // دالة السحب مع حماية من تخطي الرصيد
    void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            cout << "Withdrew: $" << amount << " | Remaining Balance: $" << balance << endl;
        } else {
            cout << "Warning: Insufficient funds or invalid amount!" << endl;
        }
    }

    double getBalance() {
        return balance;
    }
};

int main() {
    BankAccount myAcc("EG12345", 500.0);
    
    myAcc.deposit(200.0);
    myAcc.withdraw(800.0); // محاولة سحب خاطئة
    myAcc.withdraw(150.0); // سحب ناجح

    return 0;
}
Challenge 2: Tracking Object Lifetime in a Book Class
Write a class named Book containing book title and author. Design a constructor that prints a message when the book is initialized, and a destructor that prints a message indicating its destruction, to verify your understanding of object Scope in memory.

تحليل الحل البرمجي:

بص يا هندسة، هنا بنتحكم في حصر نطاق الكائن عشان نشوف المهدم وهو بينظف الذاكرة تلقائياً بمجرد قفل الأقواس:

book_tracker.cpp
#include <iostream>
#include <string>
using namespace std;

class Book {
private:
    string title;
    string author;

public:
    // منشئ بقائمة تهيئة
    Book(string t, string a) : title(t), author(a) {
        cout << "[Book Created] Name: " << title << " by " << author << endl;
    }

    // مهدم
    ~Book() {
        cout << "[Book Destroyed] Name: " << title << " is now deleted from Memory!" << endl;
    }
};

void tempFunction() {
    cout << "\n--- Entering tempFunction ---" << endl;
    Book myBook("C++ OOP Essentials", "Robert Lafore");
    cout << "--- Leaving tempFunction ---" << endl;
} // هنا يتم تدمير myBook فوراً!

int main() {
    cout << "--- Main Program Starts ---" << endl;
    tempFunction();
    cout << "--- Back to Main Program ---" << endl;
    return 0;
}
