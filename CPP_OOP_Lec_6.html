Inheritance in C++

احترف بناء وتوريد الكلاسات البرمجية وتصميم العلاقات الهندسية (Inheritance & Class Hierarchies) بأسلوب هندسي مبتكر.

ما هي الوراثة البرمجية؟ (What is Inheritance)

الوراثة هي واحدة من أقوى مميزات البرمجة كائنية التوجه (OOP) بعد الكلاسات نفسها. تتيح لك الوراثة إنشاء كلاس جديد (يسمى **Derived Class** أو كلاس ابن) بالاعتماد على كلاس موجود بالفعل (يسمى **Base Class** أو كلاس أب).

الكلاس الابن يرث تلقائياً جميع خصائص ودوال الكلاس الأب، مع إمكانية إضافة متغيرات ودوال جديدة خاصة به، دون الحاجة لإعادة كتابة الأكواد المشتركة من الصفر، ودون تعديل الكلاس الأب بأي شكل.

المهندس الكبير بيقولك بالبلدي:

بص يا هندسة، بدل ما تبني كلاس للموظف (Employee) وكلاس للعميل (Customer) وتكتب الاسم والسن والتليفون مرتين، أنت بتعمل كلاس أب عام تسميه "الشخص" (Person) وتحط فيه البيانات دي مرة واحدة، وبعدين تخلي الموظف والعميل يورثوه! كدا وفرت كود، ريحت الرام، وكتبت كود نظيف سهل التعديل.

فوائد الوراثة الأساسية:

  • إعادة استخدام الكود (Code Reusability): توفير الوقت والجهد بكتابة الأكواد العامة مرة واحدة فقط.
  • توفير الميزانية والوقت (Saves Time & Money): تطوير أسرع وصيانة أسهل للمشاريع البرمجية.
  • زيادة الموثوقية (Increases Reliability): عندما نعدل في الكلاس الأب، يُطبّق التعديل تلقائياً على كل الأبناء، مما يمنع الأخطاء التكرارية.

علاقة "Is-A" (The "is a" Relationship)

العلاقة بين الكلاس الأب (Base Class) والكلاس الابن (Derived Class) تُوصف دائماً بعلاقة **"Is-A"** (هو عبارة عن):

  • السيارة (Car) Is-A مركبة (Vehicle).
  • الموظف (Employee) Is-A إنسان (Person).
  • طالب الدراسات العليا (Postgraduate) Is-A طالب (Student).

الهيكل البنائي الأساسي (Syntax):

basic_inheritance.cpp
#include <iostream>
#include <string>
using namespace std;

// الكلاس الأب (Base Class)
class Person {
public:
    string name;
    int age;

    void talk() {
        cout << name << " is talking!" << endl;
    }
};

// الكلاس الابن (Derived Class) يرث من الأب بوضع نقطتين فوق بعض ومستوى الصلاحية
class Employee : public Person {
public:
    double salary;

    void showDetails() {
        // تلاحظ هنا أننا نقرأ name و age مباشرة كأنهما معرفين داخل الكلاس الابن!
        cout << "Name: " << name << ", Age: " << age << ", Salary: $" << salary << endl;
    }
};

int main() {
    Employee emp;
    emp.name = "Zain"; // خاصية موروثة من Person
    emp.age = 21;      // خاصية موروثة من Person
    emp.salary = 7500; // خاصية خاصة بـ Employee فقط
    
    emp.talk();        // دالة موروثة من Person
    emp.showDetails(); // دالة خاصة بـ Employee
    return 0;
}

أوضاع وصلاحيات الوراثة (Inheritance Access Modes)

عند وراثة كلاس من آخر، يجب تحديد "وضع الوراثة" (Access Specifier) وهو أحد الخيارات الثلاثة: public أو protected أو private. هذا يحدد كيف تظهر عناصر الأب للابن وللـ main.

المهندس الكبير بيقولك بالبلدي:

بص يا هندسة، النوع protected اتعمل مخصوص للوراثة! هو عبارة عن حارس بيخلي المتغيرات "سرية ومحدش يشوفها في الـ main"، لكن مسموح لـ "عيالك وأحفادك" يقرأوها ويعدلوا عليها عادي جداً. أما الـ private ده أناني، حتى الكلاس الابن مقدرش يشوفه مباشرة!

جدول تحول الصلاحيات الهندسي (Visibility Grid):

العنصر في كلاس الأب (Base Member) الوراثة العامة public الوراثة المحمية protected الوراثة الخاصة private
Public يظل Public داخل الابن يتحول إلى Protected داخل الابن يتحول إلى Private داخل الابن
Protected يظل Protected داخل الابن يظل Protected داخل الابن يتحول إلى Private داخل الابن
Private مخفي بالكامل (Not Accessible) مخفي بالكامل (Not Accessible) مخفي بالكامل (Not Accessible)

مثال عملي يوضح الصلاحيات:

access_demo.cpp
#include <iostream>
using namespace std;

class Base {
private:
    int privVar = 10;     // لا يراه أحد إلا Base نفسه
protected:
    int protVar = 20;     // يراه Base وعياله فقط
public:
    int pubVar = 30;      // يراه الجميع
};

// وراثة عامة (Public Inheritance)
class Derived : public Base {
public:
    void display() {
        // cout << privVar; // خطأ! المتغير الخاص بالأب مخفي عن الابن
        cout << "Protected Var: " << protVar << endl; // صح! يقرأ المحمي
        cout << "Public Var: " << pubVar << endl;   // صح! يقرأ العام
    }
};

int main() {
    Derived obj;
    // obj.protVar = 100; // خطأ! المتغير المحمي لا يمكن الوصول إليه في الـ main
    obj.pubVar = 300;     // صح! المتغير العام متاح للجميع في الـ main
    obj.display();
    return 0;
}

دورة حياة المشيدات والمهدمات (Object Lifetime in Inheritance)

ترتيب استدعاء المشيدات والمهدمات (Constructor/Destructor Call Order):

عند بناء كائن من كلاس ابن، يجب بناء الجزء الخاص بالأب أولاً لتجهيز الذاكرة، ثم بناء الجزء الخاص بالابن. وعند تدمير الكائن، يحدث العكس تماماً لتفريغ الذاكرة بأمان.

قاعدة ذهبية (الترتيب في الذاكرة):

الإنشاء: المشيد للأب → المشيد للابن.
التدمير: المهدم للابن → المهدم للأب (عكس الترتيب تماماً).

استدعاء مشيدات الأب ذات المعاملات (Explicit Parameterized Constructors):

إذا كان لكلاس الأب مشيد يحتوي على معاملات (Parameterized Constructor)، لن يتم استدعاؤه تلقائياً! يجب على كلاس الابن استدعاؤه صراحة في قائمة التهيئة (Initialization List) الخاصة به.

constructor_order.cpp
#include <iostream>
#include <string>
using namespace std;

class Parent {
public:
    Parent() { cout << "[1] Parent Default Constructor called" << endl; }
    Parent(string msg) { cout << "[1] Parent Parameterized: " << msg << endl; }
    ~Parent() { cout << "[4] Parent Destructor called" << endl; }
};

class Child : public Parent {
public:
    // يستدعي مشيد الأب ذو المعاملات صراحة
    Child(string text) : Parent(text) {
        cout << "[2] Child Constructor called" << endl;
    }
    ~Child() { cout << "[3] Child Destructor called" << endl; }
};

int main() {
    {
        Child c("Hello Zain");
    } // هنا ينتهي الـ Scope ويتم استدعاء المهدمات تلقائياً
    return 0;
}

إعادة تعريف الدوال (Function Overriding)

هي عملية إعادة كتابة دالة موجودة في الكلاس الأب بنفس الاسم ونفس التوقيع والبارامترات داخل الكلاس الابن، بهدف تغيير سلوكها ليناسب احتياجات الابن الخاصة.

الفرق بين Overriding و Overloading:

Function Overriding: دالتين في كلاسين مختلفين (أب وابن) بنفس الاسم والبارامترات تماماً.
Function Overloading: دوال في نفس الكلاس بنفس الاسم ولكن ببارامترات مختلفة.

overriding_demo.cpp
#include <iostream>
using namespace std;

class Animal {
public:
    void makeSound() {
        cout << "Some generic animal sound..." << endl;
    }
};

class Dog : public Animal {
public:
    // إعادة تعريف الدالة لتناسب الكلب
    void makeSound() {
        cout << "Woof! Woof!" << endl;
    }
};

int main() {
    Animal genericAnimal;
    Dog myDog;

    genericAnimal.makeSound(); // هتطبع الصوت العام
    myDog.makeSound();         // هتطبع Woof! Woof!
    
    // استدعاء دالة الأب الأصلية من كائن الابن باستخدام الـ Scope Resolution
    myDog.Animal::makeSound(); 
    return 0;
}

أنواع الوراثة والتركيب (Inheritance Types & Composition)

1. الوراثة الفردية (Single Inheritance):

كلاس ابن واحد يرث من كلاس أب واحد فقط. (وهي النوع الأبسط والأكثر استخداماً).

2. الوراثة متعددة المستويات (Multilevel Inheritance):

الابن يصبح أباً لكلاس آخر! سلسلة وراثة متتالية (مثال: Class A ← Class B ← Class C).

3. الوراثة الهرمية (Hierarchical Inheritance):

كلاس أب واحد يرث منه أكثر من كلاس ابن في نفس الوقت.

4. الوراثة المتعددة (Multiple Inheritance):

كلاس ابن واحد يرث من كلاسين أب أو أكثر في نفس الوقت! (ميزة قوية في C++ وليست مدعومة في جافا).

class Child : public Parent1, public Parent2 {
    // يرث من الأبين معاً
};

المهندس الكبير بيقولك بخصوص عيوب الوراثة:

بص يا هندسة، مش كل حاجة نحلها بالوراثة! الوراثة بتعمل ترابط قوي جداً (Tight Coupling) وممكن تعمل شجرة وراثة معقدة وصعبة الصيانة. عشان كدا في مبدأ مهم جداً اسمه **Composition** أو التركيب، وده بيمثل علاقة "Has-A" (يحتوي على) بدل علاقة "Is-A".

التركيب مقابل الوراثة (Composition vs Inheritance):

  • السيارة (Car) ليست محركاً (Engine)، ولكن السيارة "تحتوي على" محرك. لذلك لا نرث Engine في Car، بل نعرف كائن من Engine كمتغير داخل كلاس Car!
  • العلاقة هنا تسمى **Has-A relationship** وهي أفضل هندسياً لمنع التعقيد.
composition_demo.cpp
#include <iostream>
#include <string>
using namespace std;

class Engine {
public:
    void start() { cout << "Engine started! Vroom Vroom!" << endl; }
};

// بدلاً من وراثة Engine، نقوم بتضمينه كمتغير (Composition)
class Car {
private:
    Engine myEngine; // السيارة تمتلك محرك (Has-A)
    string model;

public:
    Car(string m) : model(m) {}
    
    void drive() {
        myEngine.start(); // نستخدم كائن المحرك داخلياً
        cout << model << " is ready to go!" << endl;
    }
};

int main() {
    Car myCar("Tesla Model S");
    myCar.drive();
    return 0;
}

Professional Coding Challenges:

Challenge 1: Smart Employee & Manager Hierarchy
Create a base class named Employee with private member variables name and salary. Design a parameterized constructor for it. Create a derived class named Manager that publicly inherits Employee, adds a bonus variable, and overrides a function named calculateTotalPay() to return the salary plus the bonus.

تحليل الحل البرمجي:

بص يا هندسة، هنا بنعمل كلاس الأب وبنوفر دالة Getters عشان الابن يقدر يقرأ الراتب الخاص (Private Salary) بأمان، مع تمرير بارامترات الأب في قائمة التهيئة للابن:

employee_hierarchy.cpp
#include <iostream>
#include <string>
using namespace std;

class Employee {
private:
    string name;
    double salary;

public:
    Employee(string n, double s) : name(n), salary(s) {}

    string getName() const { return name; }
    double getSalary() const { return salary; }

    double calculateTotalPay() const {
        return salary;
    }
};

class Manager : public Employee {
private:
    double bonus;

public:
    // استدعاء مشيد الأب في قائمة التهيئة
    Manager(string n, double s, double b) : Employee(n, s), bonus(b) {}

    // إعادة تعريف دالة حساب الراتب الكلي
    double calculateTotalPay() const {
        return getSalary() + bonus;
    }
};

int main() {
    Employee emp("Karem", 5000);
    Manager mgr("Zain", 12000, 3000);

    cout << "Employee: " << emp.getName() << ", Total Pay: $" << emp.calculateTotalPay() << endl;
    cout << "Manager: " << mgr.getName() << ", Total Pay: $" << mgr.calculateTotalPay() << endl;

    return 0;
}
Challenge 2: Scientific Calculator with Multiple Inheritance
Design a class named BasicCalc containing an add(double, double) function. Design another class named AdvancedCalc containing a power(double, double) function. Finally, design a derived class named ScientificCalc that inherits publicly from BOTH classes to showcase Multiple Inheritance.

تحليل الحل البرمجي:

بص يا هندسة، الوراثة المتعددة (Multiple Inheritance) بتسمح للابن يورث كذا كلاس أب في نفس الوقت بوضع فاصلة بين أسماء كلاسات الأب، كدا الـ ScientificCalc هيقدر يعمل عمليات حسابية بسيطة ومتقدمة معاً:

multiple_inheritance_calc.cpp
#include <iostream>
#include <cmath>
using namespace std;

class BasicCalc {
public:
    double add(double a, double b) {
        return a + b;
    }
};

class AdvancedCalc {
public:
    double power(double base, double exp) {
        return pow(base, exp);
    }
};

// وراثة متعددة من كلاسين معاً
class ScientificCalc : public BasicCalc, public AdvancedCalc {
public:
    void showCapabilities() {
        cout << "[Scientific Calculator] Capable of basic addition and advanced power operations." << endl;
    }
};

int main() {
    ScientificCalc calc;
    calc.showCapabilities();

    // استدعاء الدوال الموروثة من كلا الأبوين مباشرة
    cout << "5.5 + 4.5 = " << calc.add(5.5, 4.5) << endl;
    cout << "2^10 = " << calc.power(2, 10) << endl;

    return 0;
}
