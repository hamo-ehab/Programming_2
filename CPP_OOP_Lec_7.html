Polymorphism & Virtual Functions

احترف بناء الأكواد المرنة واستخدام مؤشرات الأب لتوجيه الأبناء في الذاكرة ديناميكياً مع حماية الدوال وتأمين الصداقة البرمجية.

تعدد الأشكال والدوال الافتراضية (Polymorphism & Virtual Functions)

كلمة **Polymorphism** تعني لغوياً "تعدد الأشكال" (poly = متعدد، morph = شكل). في البرمجة الكائنية، يشير المصطلح إلى قدرة المتغير أو الدالة أو المؤشر (Pointer) على اتخاذ عدة أشكال برمجية.

الهدف الأساسي هو معاملة الكائنات التي تنتمي لعائلات مختلفة (ولكنها تشترك في أب واحد) بطريقة موحدة ومبسطة، مع استدعاء السلوك الصحيح تلقائياً أثناء تشغيل البرنامج (Run-time).

المهندس الكبير بيقولك بالبلدي:

بص يا هندسة، تخيل عندك جهاز تحكم (ريموت) مكتوب عليه زرار "تشغيل" (Draw). لو الريموت ده بيشاور على مستطيل، وضغطت تشغيل هيرسم مستطيل. لو بيشاور على دايرة هيرسم دايرة. الريموت هو مؤشر الأب (Base Class Pointer)، والزرار هو الدالة الافتراضية (Virtual Function)، والأشكال هي الأبناء! بضغطة زر واحدة البرنامج بيعرف يوجه الكود للابن الصح وهو شغال!

أنواع تعدد الأشكال (Types of Polymorphism):

  1. Compile-time Polymorphism (Static/Early Binding): يتم ربط الدالة وقت الترجمة. مثل الـ **Function Overloading** والـ **Operator Overloading**.
  2. Run-time Polymorphism (Dynamic/Late Binding): يتم تحديد الدالة المستدعاة أثناء تشغيل البرنامج بناء على نوع الكائن الفعلي في الذاكرة. يتم ذلك باستخدام **Virtual Functions** مع مؤشرات الأب (Base Pointers).

الدوال الافتراضية (Virtual Functions):

الدالة الافتراضية هي دالة يتم الإعلان عنها بكلمة virtual داخل الكلاس الأب، وتتم إعادة تعريفها (Overridden) في الكلاس الابن.

بدون الكلمة المفتاحية virtual، إذا شاور مؤشر الأب على كائن ابن، واستدعى الدالة، فسيقوم C++ باستدعاء دالة الأب دائماً! (ما يعرف بالربط المبكر Early Binding). لكن عند وضع virtual، يلتزم C++ بالبحث عن الدالة داخل الابن الفعلي في الذاكرة.

#include <iostream>

الكلاسات المجردة والدوال النقية (Abstract Classes & Pure Virtual)

في بعض الأحيان، يكون كلاس الأب عاماً جداً لدرجة أنه ليس له معنى منطقي لبناء كائنات منه مباشرة! على سبيل المثال، ما معنى كائن من نوع "شكل" (Shape)؟ ليس له أبعاد محددة وليس له لون مرسوم. نحن فقط نحتاجه ليكون "قاعدة عريضة وموحدة" (Interface) يورثها الأبناء مثل المستطيل والدائرة.

هذا الكلاس يسمى **الكلاس المجرد (Abstract Class)** وهو كلاس لا يمكن إنشاء كائنات (Instantiate) منه مطلقاً.

المهندس الكبير بيقولك بالبلدي:

بص يا هندسة، الكلاس المجرد هو مجرد "عقد" أو "كتالوج مواصفات" (Interface). الأب بيقول لعياله: "أنا هعمل دالة للمساحة بس مش هكتب كودها، لأن كل واحد فيكم بيحسب مساحته بطريقة شكل! بس لو حد فيكم مورثش الدالة دي وكتب كودها بنفسه، البرنامج مش هيشتغل وهيطلع خطأ!" كدا أنت بتجبر الأبناء يلتزموا بالمعايير.

كيف نجعل الكلاس مجرداً؟ (Pure Virtual Function)

يصبح الكلاس مجرداً تلقائياً بمجرد الإعلان عن دالة افتراضية واحدة على الأقل فيه وتعيينها بالصفر = 0. تسمى هذه الدالة بـ **الدالة الافتراضية النقية (Pure Virtual Function)**. 

class Shape {
public:
    // دالة افتراضية نقية تجعل الكلاس مجرداً بالكامل
    virtual double getArea() = 0; 
};

قواعد الكلاسات المجردة الهامة:

  • لا يمكن إنشاء كائن مباشرة من الكلاس المجرد: Shape s; // خطأ! compiler error
  • يمكن إنشاء **مؤشرات** (Pointers) أو **مراجع** (References) من نوع الكلاس المجرد للإشارة إلى كائنات الأبناء.
  • أي كلاس ابن يرث كلاس مجرد **يجب** أن يعيد تعريف جميع الدوال النقية ويكتب كودها، وإلا سيتحول الكلاس الابن نفسه إلى كلاس مجرد ويمنع إنشاء كائنات منه!

مثال برمجي كامل ومحكم:

abstract_demo.cpp
#include <iostream>
using namespace std;

// كلاس مجرد (Abstract Class)
class Shape {
protected:
    double width, height;

public:
    Shape(double w = 0, double h = 0) : width(w), height(h) {}

    // دالة افتراضية نقية
    virtual double getArea() = 0; 
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : Shape(w, h) {}

    // مجبرين نعيد تعريف دالة المساحة
    double getArea() override {
        return width * height;
    }
};

class Triangle : public Shape {
public:
    Triangle(double w, double h) : Shape(w, h) {}

    double getArea() override {
        return 0.5 * width * height;
    }
};

int main() {
    // Shape s; // خطأ برمي! لا يمكن بناء كائن مباشر من كلاس مجرد

    Shape* s1 = new Rectangle(10, 5);
    Shape* s2 = new Triangle(10, 5);

    cout << "Rectangle Area: " << s1->getArea() << endl; // هيطبع 50
    cout << "Triangle Area: " << s2->getArea() << endl;  // هيطبع 25

    delete s1;
    delete s2;
    return 0;
}

دوال وفئات الصداقة (Friend Functions & Friend Classes)

أحد أهم مبادئ الـ OOP هو **الكبسلة (Encapsulation)** لمنع الدوال الخارجية من قراءة أو تعديل المتغيرات الخاصة والسرية (private و protected).

ولكن في بعض الحالات الهندسية النادرة، قد تحتاج دالة خارجية أو كلاس خارجي بالكامل للوصول المباشر والسريع لهذه البيانات السرية دون استخدام Getters و Setters. هنا يأتي دور **الصداقة (Friendship)** في C++.

المهندس الكبير بيقولك بخصوص الصداقة:

بص يا هندسة، الصداقة دي تصريح أمني استثنائي! الكلاس بيعلن داخل كوده وبيقول: "الدالة دي أو الكلاس ده صاحبي وصديقي الصدوق، مسموح له يدخل غرفتي الخاصة ويقرأ بياناتي السرية مباشرة!"
افتكر القواعد الذهبية دي كويس جداً:
1. ليست متبادلة (Not Mutual): لو B صديق A، ده مش معناه إن A صديق لـ B تلقائياً!
2. لا تُورث (Not Inherited): لو B صديق A، عيال B مش أصدقاء لـ A، وB مش صديق لأبناء A!

1. الدالة الصديقة (Friend Function):

هي دالة **ليست** عضواً في الكلاس (مستقلة وتعرف في الخارج كدالة عادية)، ولكن يتم وضع نموذجها (Prototype) داخل الكلاس مسبوقاً بكلمة friend.

friend_function.cpp
#include <iostream>
using namespace std;

class Box {
private:
    double width;

public:
    Box(double w) : width(w) {}

    // الإعلان عن الدالة كصديقة للكلاس
    friend void printWidth(Box b); 
};

// تعريف الدالة في الخارج كدالة عادية تماماً (بدون Scope Resolution أو friend)
void printWidth(Box b) {
    // تلاحظ هنا أننا نقرأ b.width الخاص مباشرة بدون دوال Get!
    cout << "Width of box: " << b.width << endl; 
}

int main() {
    Box box(12.5);
    printWidth(box); // استدعاء عادي جداً
    return 0;
}

2. الكلاس الصديق (Friend Class):

يمكن الإعلان عن كلاس كامل كصديق لكلاس آخر. في هذه الحالة، تصبح جميع دوال وأعضاء الكلاس الصديق قادرة على الوصول للمتغيرات الخاصة والمحمية للكلاس الأصلي.

friend_class.cpp
#include <iostream>
#include <string>
using namespace std;

class Database {
private:
    string adminPassword = "SuperSecretPassword123";

public:
    // الإعلان عن كلاس المحاسب أو الفاحص كصديق
    friend class SystemAuditor; 
};

class SystemAuditor {
public:
    void auditDatabase(Database db) {
        // الوصول للباسورد الخاص مباشرة بأمان وسرعة!
        cout << "[Security Audit] Accessing Admin Password: " << db.adminPassword << endl;
    }
};

int main() {
    Database db;
    SystemAuditor auditor;
    auditor.auditDatabase(db);
    return 0;
}

Professional Coding Challenges:

Challenge 1: Dynamic Payment Gateway
Create an abstract base class named PaymentMethod. It must contain a pure virtual function processPayment(double amount) = 0. Design two derived classes: CreditCard and PayPal. Show how to process payments dynamically during run-time using a pointer of type PaymentMethod*.

تحليل الحل البرمجي:

بص يا هندسة، هنا بننشئ الكلاس المجرد كبوابة دفع عامة، وبنجبر الكلاسات الفرعية توفر كود خاص لكل منها للتعامل مع العملية بأمان وتوفير تجربة دفع ديناميكية:

payment_gateway.cpp
#include <iostream>
using namespace std;

// كلاس مجرد بالكامل (Interface)
class PaymentMethod {
public:
    virtual void processPayment(double amount) = 0; // دالة نقية
    virtual ~PaymentMethod() {} // من الممارسات الممتازة وضع مهدم افتراضي
};

class CreditCard : public PaymentMethod {
public:
    void processPayment(double amount) override {
        cout << "[Credit Card Payment] Processing transaction of $" << amount 
             << " through secured bank gateway." << endl;
    }
};

class PayPal : public PaymentMethod {
public:
    void processPayment(double amount) override {
        cout << "[PayPal Payment] Authorizing and sending $" << amount 
             << " using secure tokenized email system." << endl;
    }
};

int main() {
    PaymentMethod* paymentGateway = nullptr; // مؤشر الأب

    // العميل قرر يدفع بالفيزا
    paymentGateway = new CreditCard();
    paymentGateway->processPayment(150.0); // استدعاء الفيزا ديناميكياً
    delete paymentGateway;

    // العميل قرر يدفع بـ PayPal
    paymentGateway = new PayPal();
    paymentGateway->processPayment(45.99); // استدعاء باي بال ديناميكياً
    delete paymentGateway;

    return 0;
}
Challenge 2: Secure Bank Auditor Tool (Friend Class)
Create a class named BankAccount containing private member variables accountHolder and balance. Declare another class BankAuditor as a friend of BankAccount. Inside BankAuditor, write a function to print the account balance without using public helper functions of the bank account.

تحليل الحل البرمجي:

بص يا هندسة، هنا بنعلن إن كلاس الفاحص صديق للبنك. ده بيدي الفاحص صلاحيات أمنية لقراءة الرصيد السري مباشرة بدون كتابة دوال Getters عامة تكشف الرصيد لباقي البرنامج:

bank_audit.cpp
#include <iostream>
#include <string>
using namespace std;

class BankAccount {
private:
    string accountHolder;
    double balance;

public:
    BankAccount(string holder, double bal) : accountHolder(holder), balance(bal) {}

    // تعيين الكلاس الصديق داخل الكود الخاص بالبنك
    friend class BankAuditor; 
};

class BankAuditor {
public:
    void printReport(const BankAccount& acc) {
        // قراءة المتغيرات الخاصة مباشرة!
        cout << "[BANK AUDIT REPORT]" << endl;
        cout << "Holder: " << acc.accountHolder << endl;
        cout << "Current Balance: $" << acc.balance << endl;
        
        if (acc.balance > 100000) {
            cout << "Status: Premium VIP Account." << endl;
        } else {
            cout << "Status: Standard Active Account." << endl;
        }
    }
};

int main() {
    BankAccount myAccount("Zain", 150000.0);
    BankAuditor auditor;

    // الفاحص يطبع تقرير الحساب مباشرة
    auditor.printReport(myAccount);

    return 0;
}
